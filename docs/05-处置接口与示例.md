# 05 处置接口与示例（重点）

Auth：除另行说明外均为 `@engineer_required`（工程师 Session）。

业务规则见 [04-处置规范.md](./04-处置规范.md)。

---

## 1. 可发起行为目录

### `GET /eng/api/dispose_actions`

无 Query。

**成功 `data` 示例：**

```json
[
  { "dispose": 1, "label": "放行", "group": "engineer" },
  { "dispose": 2, "label": "降级", "group": "engineer" },
  { "dispose": 3, "label": "重测", "group": "engineer" },
  { "dispose": 5, "label": "可靠性分析", "group": "engineer" }
]
```

---

## 2. 工程备注（处置附属）

### `GET /eng/api/notes?product_id={PRODUCT_ID}`

`product_id` 为型号代码（与 Holding 行 `PRODUCT_ID` 一致），必填。

返回所属型号下可用工程备注列表（`IS_AVAILABLE=1`），供处置页下拉；选中文本填入 `dispose_note`。

备注库 CRUD / MES sync **不是**本客户端主功能，此处仅读取。

---

## 3. 提交处置

### `POST /eng/api/dispose`

**Body 字段：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `hold_record_id` | int | 是 | 记录 ID |
| `dispose` | int | 条件 | 非 WLT 必填：`1/2/3/5`；WLT 可省略，由 `wafer_actions` 汇总 |
| `wafer_actions` | array | 条件 | WLT **必填**；非 WLT 禁止 |
| `downgrades` | array | 降级时 | 非 WLT：`[{from,to},...]` |
| `retest_grades` | array | 重测时 | 非 WLT：等级列表 |
| `retest_code` | string | 否 | 旧版兼容；新 WLT 勿用 |
| `dispose_detail` | string | 否 | 一般勿传；由服务端生成 |
| `dispose_note` | string | 否 | 工程备注 ≤1024 |
| `dispose_manual_note` | string | 条件 | 手输备注 ≤1024；可靠性分析之后的放行/降级**必填** |
| `confirm_interval` | bool | 条件 | 距可靠性分析不足 30 分钟时须为 `true` |

路由层：`dispose` 与 `wafer_actions` **至少提供其一**。

### 成功响应

```json
{
  "code": 200,
  "msg": "处置成功",
  "data": {
    "hold_record_id": 123,
    "circulation_id": 456,
    "dispose": 2,
    "dispose_label": "降级",
    "disposed_owner_id": 12,
    "next_owner_id": 181,
    "dispose_detail": "DG:HA>F",
    "dispose_note": "工程备注文本",
    "dispose_manual_note": null,
    "status": 2
  }
}
```

成功后：放行/降级/重测的 `next_owner_id` 一般为生产 OP（181）；可靠性分析的 `next_owner_id` 仍是操作工程师；`status` 等于本次 `dispose`。

### 常见失败 msg（多为 HTTP 400；30 分钟间隔为 HTTP 409）

| msg 关键词 | 含义 |
| --- | --- |
| `hold_record_id 必填` | 缺主键 |
| `dispose 与 wafer_actions 至少提供其一` | 路由校验 |
| `非工程师处置行为` | dispose 不在 1/2/3/5 |
| `仅当前负责人可处置该记录` | 非待办人或已流转 |
| `记录已关闭，无法继续处置` | STATUS=99 |
| `WLT 处置须提供 wafer_actions` | RECORD_TYPE=2 缺按片 |
| `仅 WLT 处置单支持按片 wafer_actions` | 非 WLT 传了 wafer_actions |
| `须一次性处置全部 wafer` | 漏片 |
| `未知 wafer` / `wafer 重复` | 按片校验 |
| `dispose 与按片汇总不一致` | 顶层 dispose ≠ 汇总 |
| `降级须至少变更一个等级` | downgrades 无效 |
| `重测须至少选择一个等级` | retest_grades 空 |
| `夹具重测须填写 code` | fixture 缺 `@数字` |
| `dispose_note 最长 1024` / `dispose_detail 最长 4000` | 超长 |
| `可靠性分析之后仅允许放行或降级` | 上一工程师处置为 5 |
| `可靠性分析之后须手输备注` | 缺 `dispose_manual_note` |
| `距上次可靠性分析不足30分钟` | HTTP 409，需 `confirm_interval=true` |

## 4. FT / FVI 请求示例

先 `GET /eng/api/records/{id}` 确认 `RECORD_TYPE` 为 `0` 或 `1`，并取 `GRADES`。

### 4.1 放行

```json
{
  "hold_record_id": 123,
  "dispose": 1,
  "dispose_note": "良率可接受",
  "dispose_manual_note": "可选手输"
}
```

### 4.2 降级

```json
{
  "hold_record_id": 123,
  "dispose": 2,
  "downgrades": [
    { "from": "HA", "to": "F" },
    { "from": "FB", "to": "F" }
  ],
  "dispose_note": "按规范降级"
}
```

服务端生成：`DISPOSE_DETAIL = "DG:HA>F;FB>F"`。

### 4.3 重测（按等级）

```json
{
  "hold_record_id": 123,
  "dispose": 3,
  "retest_grades": ["F", "HA"],
  "dispose_manual_note": "关注边缘"
}
```

服务端生成：`DISPOSE_DETAIL = "RT:F,HA"`。

### 4.4 可靠性分析

```json
{
  "hold_record_id": 123,
  "dispose": 5,
  "dispose_manual_note": "送可靠性"
}
```

`DISPOSE_DETAIL` 一般为 `null`。下一节点仍是操作工程师；生产并行待留样，点「留样完成」(65) 即可从生产待办消掉，不堵塞工程师。

可靠性分析之后仅允许放行/降级，且必须手输备注。不足 30 分钟连续操作时服务端返回：

```json
{
  "code": 409,
  "msg": "距上次可靠性分析不足30分钟，确认后请再次提交",
  "data": { "need_interval_confirm": true }
}
```

确认后在原 body 增加 `"confirm_interval": true` 再提交。

## 5. WLT 请求示例

先取 `WAFERS`（例如 `["#01","#02","#03"]`），`wafer_actions` 必须覆盖全部。

```json
{
  "hold_record_id": 123,
  "wafer_actions": [
    { "wafer": "#01", "dispose": 1 },
    {
      "wafer": "#02",
      "dispose": 2,
      "downgrade_mode": "main_split"
    },
    {
      "wafer": "#03",
      "dispose": 3,
      "retest_mode": "fixture_a",
      "retest_codes": "@1@361"
    }
  ],
  "dispose_note": "按片意见"
}
```

说明：

- 可省略顶层 `dispose`；上例汇总为 `3`（存在重测）。
- 若写 `"dispose": 3` 必须与汇总一致。
- `wafer` 也可用字段名 `wafer_id`。
- `downgrade_mode`：仅 `main_split` | `main_nosplit`。
- `retest_mode`：`full`（勿填 code）| `fixture_a` | `fixture_b`（必填 `retest_codes`）。

服务端 `DISPOSE_DETAIL` 示例：

```text
#01，放行;#02，降级，降main拆批;#03，重测，重测A夹具，@1@361
```

### 整片重测片

```json
{ "wafer": "#04", "dispose": 3, "retest_mode": "full" }
```

### 可靠性分析片

```json
{ "wafer": "#05", "dispose": 5 }
```

若任一片为 `5`，记录级汇总为 `5`。

## 6. 推荐调用顺序（处置段）

```text
GET  /eng/api/records/{id}          → GRADES / WAFERS / CAN_DISPOSE / AFTER_RELIABILITY_ANALYZE
GET  /eng/api/notes?product_id=...  → 可选备注
GET  /eng/api/dispose_actions       → 可选，也可本地写死 1/2/3/5
POST /eng/api/dispose               → 提交
```
