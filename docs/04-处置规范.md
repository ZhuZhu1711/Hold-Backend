# 04 处置规范（重点）

本文描述工程师侧处置的业务规则，实现见 `app/controllers/dispose_ctrl.py`。

工程师处置 = **意见**：写入 `CIRCULATION_HISTORY`，回写 `FT_HOLD_RECORD.LAST_CIRCULATION_ID` / `STATUS`；**不改写 `GRADE_NUM`**。物理落地由生产侧执行。

---

## 1. 状态流转（工程师视角）

```text
系统创建 (dispose=0)
  NEXT = 型号工程师 (PRODUCT_INFO.PRO_ENG_ID)
  STATUS = 0
        │
        ▼
工程师待办 (CURRENT_OWNER = 本人)
  执行 1 / 2 / 3 / 5
  ├─ 1 / 2 / 3 → NEXT = 生产 OP (默认 ID=181)，STATUS = 本次 dispose
  └─ 5 可靠性分析 → NEXT = 操作工程师本人，STATUS = 5
        │
        ├─ 生产并行看到待留样，可点 65 留样完成（不改当前负责人）
        └─ 工程师继续：仅 1 放行 / 2 降级（须手输备注）
              │
              ▼
生产节点（放行/降级/重测落地）
  ├─ 8 回退 → 返回工程师
  └─ 99 关闭 → NEXT=null，终态
```

常量：`PRODUCTION_OP_ID = 181`，`SYSTEM_USER_ID = 1`。

本客户端**只发起工程师处置**；生产动作由其它系统完成。工程师提交放行/降级/重测后该单通常离开本人待办（`CAN_DISPOSE` 变为 false）。可靠性分析后下一节点仍是自己，可立刻继续放行/降级。

---

## 2. 工程师处置码

| DISPOSE | 标签 | NEXT_OWNER | DISPOSED_OWNER |
| --- | --- | --- | --- |
| `1` | 放行 | 181（生产 OP） | 操作工程师 |
| `2` | 降级 | 181 | 操作工程师 |
| `3` | 重测 | 181 | 操作工程师 |
| `5` | 可靠性分析 | 操作工程师（自循环） | 操作工程师 |
| `7` | 转交 | 型号工程师 | — | **当前屏蔽**，不可发起 |

`GET /eng/api/dispose_actions` 仅返回 `1/2/3/5`。

生产侧码（客户端勿发）：`65` 留样完成、`8` 回退、`99` 关闭。`6`/`66` 分析返回已废弃，仅历史展示。

系统创建：`0`（合批任务写入，非客户端）。

### 可靠性分析之后

当最新一次工程师处置（`DISPOSE ∈ {1,2,3,5,7}`，忽略生产侧流转）为 `5` 时：

- 只允许 `1` 放行、`2` 降级（含 WLT 各片）
- `dispose_manual_note` **必填**
- 距该次 `5` 不足 30 分钟：首次提交返回 `code=409` 且 `need_interval_confirm=true`；确认后带 `confirm_interval=true` 再提交

单条详情额外字段：`AFTER_RELIABILITY_ANALYZE`、`ALLOWED_DISPOSES`、`REQUIRE_MANUAL_NOTE`、`ANALYZE_INTERVAL_WARN`、`LAST_ANALYZE_DTTM`。

---

## 3. 权限规则

工程师执行 `1/2/3/5` 时须同时满足：

1. 记录未关闭（`STATUS != 99`）
2. 当前负责人 = 本人（最新流转的 `NEXT_OWNER_ID`）
3. 型号归属：列表/单条接口已过滤；处置写路径再校验当前负责人

不满足时常见错误：`仅当前负责人可处置该记录`、`记录已关闭，无法继续处置`。

## 4. 处置单划分（RECORD_TYPE）

入池为 `FT_HOLD_RECORD` 的规则摘要（合批任务判定；客户端只读 `RECORD_TYPE`）：

| RECORD_TYPE | 名称 | 规则摘要 |
| --- | --- | --- |
| `0` | FT 异常反馈单 | 产品 `*-3.5`，Hold 码 023/024/025/027/028/AQL_HOLD，站点 ∉ FAOIFINISH/FFVI |
| `1` | FVI 异常反馈单 | Hold 码 023，站点 ∈ FAOIFINISH/FFVI |
| `2` | WLT 异常反馈单 | 产品 `*-2.6`，Hold 码 004/022，站点 WOQC |

不满足规则的 hold_info **不会**成为可处置 record。手提创建（`SOURCE=1`）不经合批，直接写 record，见 [07-手提Hold.md](./07-手提Hold.md)。

`AQL_HOLD`：分类为 FT 异常反馈单；**不跑数据分析**，分析入口展示附件图（`ANNEX_FTP_PATH` 为空则不显示）。

`028`（重码风险）：分类为 FT 异常反馈单；合批时与同 lot/wafer 的良率、缺陷率 hold **分列**，各写一条 record。

`025` + 站点 `FPQC` 且 `HOLD_REASON` 含 `FUTURE HOLD`：预 hold，**不参与合批**。

合批任务**不再**按 `FT_HOLD_INFO.HOLDING` 自动结单。关闭仍走生产处置或手工脚本。

处置入参形态依赖 `RECORD_TYPE`：

| 类型 | 入参方式 |
| --- | --- |
| FT / FVI（0/1） | 顶层 `dispose` + 可选 `downgrades` / `retest_grades` |
| WLT（2） | **必须** `wafer_actions`（覆盖全部片）；顶层 `dispose` 可省略 |

---

## 4.1 HOLD_WAFER_ATTR（片属性比特位）

`FT_HOLD_RECORD.HOLD_WAFER_ATTR` 用十进制存比特位，合批任务与手提创建写入时由服务端按源 `LOT_ID` / `EQUIP_ID` / `STATION` 计算（WLT 合批截断 `LOT_ID` 前用原值）。缺省 `0`。多 bit 可 OR。

| bit | 值 | 名称 | 判定 |
| --- | --- | --- | --- |
| 0 | 1 | 真空包 | `LOT_ID` 不含 `-`，且以 `VSH`/`TSH` 开头（忽略大小写）；站点非 WLT（不以 `WLT` 开头且不是 `WOQC`） |
| 1 | 2 | 梓一合批 | 机台号 **≥ 200**；`LOT_ID` 含 `-` 且 `-` 后纯数字位数 **> 2** |
| 2 | 4 | IQC_ATE 合批 | 机台号 **< 200**；同上 lot 后缀规则 |
| 3 | 8 | ATE 合批 | 不含 `-`，且以 `A` 开头 |
| 4 | 16 | FVI 合批 | 不含 `-`，且以 `I` 开头 |

机台号：`EQUIP_ID` 去空白后须为纯数字；无法解析则不打梓一 / IQC_ATE。`200` 归梓一。

## 5. 字段语义与长度

| 字段 | 库列 | 长度 | 说明 |
| --- | --- | --- | --- |
| 规则化详情 | `DISPOSE_DETAIL` | ≤4000 | 降级/重测/WLT 按片描述；**服务端生成**，客户端勿手拼（除非兼容旧格式） |
| 工程备注 | `DISPOSE_NOTE` | ≤1024 | 工程师从备注库选择的文本 |
| 手输备注 | `DISPOSE_MANUAL_NOTE` | ≤1024 | 任意处置可选；可靠性分析之后的放行/降级**必填** |

一次处置事务：

1. `INSERT CIRCULATION_HISTORY`（`DISPOSE_SOURCE='SYS'`，`DISPOSE_TYPE=dispose`）
2. `UPDATE FT_HOLD_RECORD SET LAST_CIRCULATION_ID, STATUS`（`STATUS = dispose`）
3. **不更新** `GRADE_NUM`

## 6. 非 WLT（FT / FVI）详情规则

服务端按结构化入参生成 `DISPOSE_DETAIL`（不含备注）：

### 降级 `dispose=2`

- 入参：`downgrades: [{ "from": "HA", "to": "F" }, ...]`
- 至少有一个真实变更（`from != to`）
- 同一源等级只能出现一次
- 生成：`DG:HA>F;FB>F`

### 重测 `dispose=3`

- 入参：`retest_grades: ["F","HA"]` → `RT:F,HA`
- 旧版 WLT 单 code：`retest_code` → `RT:CODE=...`（新客户端 WLT 请用 `wafer_actions`）
- `retest_grades` 与 `retest_code` **互斥**

### 放行 `1` / 可靠性分析 `5`

- `DISPOSE_DETAIL` 一般为 `null`
- 备注走 `dispose_note` / `dispose_manual_note`

## 7. WLT 按片处置（RECORD_TYPE=2）

### 强制规则

1. 必须传 `wafer_actions` 数组
2. 必须覆盖记录全部 `WAFERS`（来自 `GET /eng/api/records/{id}`）
3. 不可重复 wafer；不可出现未知 wafer
4. 各片 `dispose` 仅允许 `1/2/3/5`
5. 写库仍是**一条**流转；记录级 `DISPOSE`/`STATUS` 由各片汇总：

**任一 5 → 5；否则任一 3 → 3；否则任一 2 → 2；否则 1。**

若客户端同时传顶层 `dispose`，必须与汇总一致，否则拒绝。

### 单片字段

| dispose | 必填子字段 | 说明 |
| --- | --- | --- |
| `1` / `5` | — | `#01，放行` / `#02，可靠性分析` |
| `2` | `downgrade_mode` | 仅 `main_split`（降main拆批）或 `main_nosplit`（降main不拆批）；**不指定等级** |
| `3` | `retest_mode` | `full`：整片重测，**禁止**填 code；`fixture_a` / `fixture_b`：**必须** `retest_codes` 如 `@1@361` |

`retest_codes` 正则：`^(@\d+)+$`。

### DISPOSE_DETAIL 示例（服务端生成）

```text
#02，降级，降main拆批;#03，降级，降main不拆批;#05，重测，整片重测;#06，重测，重测A夹具，@1@361
```

片间 `;`，片内中文逗号 `，`。生产落地以该字段为准。

---

## 8. 客户端实现要点

1. 仅在 `CAN_DISPOSE === true` 时开放提交。
2. 按 `RECORD_TYPE` 切换 FT/FVI 表单 vs WLT 按片表单。
3. WLT 提交前用 `WAFERS` 校验覆盖完整性。
4. 不要本地改 `GRADE_NUM`；不要期望提交后等级变化。
5. 提交成功后刷新列表；放行/降级/重测后该单通常不再出现在 `pending_only=1` 结果中。可靠性分析后仍在本人待办。
6. 若 `AFTER_RELIABILITY_ANALYZE`：只展示放行/降级；手输备注必填；`ANALYZE_INTERVAL_WARN` 时先确认再带 `confirm_interval` 提交。
