# 01 鉴权与通用约定

## 1. 基本信息

| 项 | 说明 |
| --- | --- |
| 协议 | HTTP / HTTPS |
| 默认端口 | `50001` |
| Base URL 示例 | `http://{host}:50001` |
| 数据格式 | JSON（`Content-Type: application/json`） |
| 字符编码 | UTF-8 |
| 鉴权 | Flask 签名 Session Cookie，或外部系统 Header `X-Hold-Token`（**无 JWT**） |

工程师客户端须使用 **ROLE = 1（产品工程师）** 账号登录。

## 2. 角色

| ROLE | 名称 | 本客户端 |
| --- | --- | --- |
| `0` | 超级管理员 | 不使用 |
| `1` | 产品工程师 | **目标角色** |
| `9` | 生产 | 不使用 |

登录接口允许上述三种角色；客户端拿到 `data.role` 后应校验为 `1`，否则提示账号类型不匹配。

## 3. 登录

### `POST /api/login`

**Auth：** 无

**Body：**

```json
{
  "employee_no": "工号",
  "password": "e10adc3949ba59abbe56e057f20f883e",
  "remember": true
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `employee_no` | string | 是 | 工号 |
| `password` | string | 是 | **MD5(明文密码) 的 32 位小写 hex**，禁止传明文。例：明文 `123456` → `e10adc3949ba59abbe56e057f20f883e` |
| `remember` | bool | 否 | 默认 `true`；持久 Cookie（约 30 天，请求滑动续期） |

**客户端约定：** 先对用户输入做 UTF-8 MD5，再把 hex 填入 `password` 发起请求。服务端用该值与库中 `USERS.PASSWORD`（已存 MD5）比对。

**成功（200）：**

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "id": 12,
    "name": "张三",
    "role": 1,
    "employee_no": "A0001",
    "remember": true,
    "redirect": "/eng/dashboard"
  }
}
```

响应会下发 Cookie，名称：`hold_session`（HttpOnly，SameSite=Lax）。

**失败：**

| HTTP | code | 场景 |
| --- | --- | --- |
| 401 | 401 | 用户不存在 / 密码错误 |
| 403 | 403 | 角色不在允许列表 |

### 后续请求

- 浏览器 / 原生 HTTP 客户端须携带 Cookie（如 `credentials: 'include'` 或 `Cookie: hold_session=...`）。
- Session 内关键字段：`user_id`、`user_name`、`employee_no`、`role`。

### 外部系统固定 Token（与 Cookie 双通道）

外部系统可不登录，在每次请求带固定 Header：

```
X-Hold-Token: <与服务端 HOLD_API_TOKEN 相同的字符串>
```

| 项 | 说明 |
| --- | --- |
| 开关 | 环境变量 `HOLD_API_TOKEN`；未配置或空字符串则关闭，Header 无效 |
| 权限 | 匹配后跳过登录与角色校验，可调所有已保护 API |
| 操作人 | 无 Cookie 时按系统用户写入 Session（`SYSTEM_USER_ID=1`，角色 root，名称 `API_TOKEN`） |
| 与 Cookie | 二选一即可；人类用户 / 工程师客户端仍走登录 Cookie，不必改 |

未带合法 Cookie 且 Token 不匹配时，仍返回 401 `请先登录`。

`/eng/*` 接口仍按当前用户滤所属型号；token 注入的是系统账号，外部对接请优先用 `/admin/hold/api/...`。

### 退出

`GET /logout` — 清空 Session。客户端也可丢弃本地 Cookie。

## 4. 统一响应结构

成功：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": {}
}
```

分页列表额外字段：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": [],
  "total": 100,
  "page": 1,
  "page_size": 20,
  "pages": 5
}
```

常见错误 `code` / HTTP：

| code | 含义 |
| --- | --- |
| 400 | 参数或业务校验失败 |
| 401 | 未登录（`请先登录`） |
| 403 | 已登录但角色/归属不符 |
| 404 | 资源不存在 |
| 500 | 服务异常 |

工程师专用接口使用 `@engineer_required`：非工程师角色返回 403。

## 5. 分页约定

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `page` | int | 1 | 从 1 起 |
| `page_size` | int | 20 | 每页条数（服务端有上限，通常最大 200） |

列表接口不做全量返回，请按页拉取。

## 6. 客户端注意点

1. **登录前对密码做 MD5**，请求体只传 hex，不传明文。
2. 登录成功后校验 `data.role === 1`。
3. 登录成功后调用 `GET /api/common_data/ftp/status` 一次；`data.available === false` 时提示「会影响数据分析」，**不要阻断登录或处置**。
4. Cookie 跨域时需服务端 CORS 与 `credentials` 配置匹配（本仓库 Web UI 同域部署为主）。
5. HTTPS 环境可将服务端 `HOLD_SESSION_SECURE=1`，Cookie 带 Secure。

### FTP 探活

`GET /api/common_data/ftp/status`

**Auth：** 已登录

探活数据分析用 testlog FTP（bysite / testlog 下载）。接口本身成功时 HTTP/code 均为 200；用 `data.available` 判断 FTP 是否通。

```json
{
  "code": 200,
  "msg": "FTP 可用",
  "data": {
    "available": true,
    "host": "172.18.200.250",
    "latency_ms": 42,
    "impact": null
  }
}
```

FTP 挂了时 `available` 为 `false`，`impact` 为给用户看的说明（数据分析可能受影响，Hold 流转不受影响）。
