# 01 鉴权与通用约定

## 1. 基本信息

| 项 | 说明 |
| --- | --- |
| 协议 | HTTP / HTTPS |
| 默认端口 | `50001` |
| Base URL 示例 | `http://{host}:50001` |
| 数据格式 | JSON（`Content-Type: application/json`） |
| 字符编码 | UTF-8 |
| 鉴权 | Flask 签名 Session Cookie，或外部系统 Header `X-Hold-Token`（**无 JWT**） |

工程师客户端须使用 **ROLE = 1（产品工程师）** 账号登录。

## 2. 角色

| ROLE | 名称 | 本客户端 |
| --- | --- | --- |
| `0` | 超级管理员 | 不使用 |
| `1` | 产品工程师 | **目标角色** |
| `9` | 生产 | 不使用 |

登录接口允许上述三种角色；客户端拿到 `data.role` 后应校验为 `1`，否则提示账号类型不匹配。

## 3. 登录

### `POST /api/login`

**Auth：** 无

**Body：**

```json
{
  "employee_no": "工号",
  "password": "e10adc3949ba59abbe56e057f20f883e",
  "remember": true
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `employee_no` | string | 是 | 工号 |
| `password` | string | 是 | **MD5(明文密码) 的 32 位小写 hex**，禁止传明文。例：明文 `123456` → `e10adc3949ba59abbe56e057f20f883e` |
| `remember` | bool | 否 | 默认 `true`；持久 Cookie（约 30 天，请求滑动续期） |

**客户端约定：** 先对用户输入做 UTF-8 MD5，再把 hex 填入 `password` 发起请求。服务端用该值与库中 `USERS.PASSWORD`（已存 MD5）比对。

**成功（200）：**

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "id": 12,
    "name": "张三",
    "role": 1,
    "employee_no": "A0001",
    "remember": true,
    "must_change_password": false,
    "redirect": "/eng/dashboard"
  }
}
```

响应会下发 Cookie，名称：`hold_session`（HttpOnly，SameSite=Lax）。

`must_change_password` 为 `true` 时，`redirect` 为 `/change-password`，并额外返回 `change_password_url`（一次性 Web SSO 链接，打开后进入改密页）。Web 跟 `redirect` 进入改密页；**桌面客户端应拒绝进入主界面**，用 `change_password_url` 打开浏览器帮用户改密。未改密前，除改密页、改密接口、Web SSO 票据与登出外，其它已登录 API 返回 403。

**失败：**

| HTTP | code | 场景 |
| --- | --- | --- |
| 401 | 401 | 用户不存在 / 密码错误 |
| 403 | 403 | 角色不在允许列表 |
| 429 | 429 | 同一 IP 60 秒内超过 10 次登录，或同一工号 15 分钟内失败超过 5 次。文案：`请求过于频繁，请稍后再试`（响应带 `Retry-After`） |

### 密码规则

建用户（`POST /admin/users/api`）与改密（`POST /api/change-password`）提交**明文**（不要传 MD5）。服务端校验后再存 MD5：

- 至少 6 位，须同时包含字母和数字
- 不能与工号相同（忽略大小写）
- 禁止常见弱密码（如 `123456`、`abc123`）

登录仍只传 MD5 hex。文档里 `123456` 的 hash 仅用于说明算法，该口令已禁止设为新密码。

现有账号在 `USERS.MUST_CHANGE_PWD=1` 时，用旧密码登录 Web 后必须先改密。上线前执行 [`docs/sql/ddl/USERS_MUST_CHANGE_PWD.sql`](./sql/ddl/USERS_MUST_CHANGE_PWD.sql)（`USERS` 为 debug/release 共用表）。部署后尚未改密的旧 Session Cookie 也会被拦到改密页。

### `GET /change-password`

**Auth：** 已登录。强制改密用户只能打开本页、改密接口、Web SSO 票据和登出。页面展示当前用户名与工号。

### `POST /api/change-password`

**Auth：** 已登录

**Body：**

```json
{
  "old_password": "原密码明文",
  "new_password": "新密码明文",
  "confirm_password": "新密码明文"
}
```

成功后 `MUST_CHANGE_PWD` 置 0，JSON 带 `data.redirect` 为角色首页。

### 后续请求

- 浏览器 / 原生 HTTP 客户端须携带 Cookie（如 `credentials: 'include'` 或 `Cookie: hold_session=...`）。
- Session 内关键字段：`user_id`、`user_name`、`employee_no`、`role`、`must_change_password`。

### 外部系统固定 Token（与 Cookie 双通道）

外部系统可不登录，在每次请求带固定 Header：

```
X-Hold-Token: <与当前模式对应环境变量相同的字符串>
```

| 项 | 说明 |
| --- | --- |
| 开关 | release 读 `HOLD_API_TOKEN`，`--mode debug` 读 `HOLD_API_TOKEN_DEBUG`；未配置或空字符串则关闭，Header 无效 |
| 权限 | 匹配后跳过登录与角色校验，可调所有已保护 API |
| 操作人 | 无 Cookie 时按系统用户写入 Session（`SYSTEM_USER_ID=1`，角色 root，名称 `API_TOKEN`） |
| 与 Cookie | 二选一即可；人类用户 / 工程师客户端仍走登录 Cookie，不必改 |

未带合法 Cookie 且 Token 不匹配时，仍返回 401 `请先登录`。

`/eng/*` 接口仍按当前用户滤所属型号；token 注入的是系统账号，外部对接请优先用 `/admin/hold/api/...`。

### 退出

`GET /logout` — 清空 Session。客户端也可丢弃本地 Cookie。

## 4. 统一响应结构

成功：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": {}
}
```

分页列表额外字段：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": [],
  "total": 100,
  "page": 1,
  "page_size": 20,
  "pages": 5
}
```

常见错误 `code` / HTTP：

| code | 含义 |
| --- | --- |
| 400 | 参数或业务校验失败 |
| 401 | 未登录（`请先登录`） |
| 403 | 已登录但角色/归属不符；或须先改密 |
| 404 | 资源不存在 |
| 429 | 登录过于频繁 |
| 500 | 服务异常 |

工程师专用接口使用 `@engineer_required`：非工程师角色返回 403。

## 5. 分页约定

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `page` | int | 1 | 从 1 起 |
| `page_size` | int | 20 | 每页条数（服务端有上限，通常最大 200） |

列表接口不做全量返回，请按页拉取。

## 6. 客户端注意点

1. **登录前对密码做 MD5**，请求体只传 hex，不传明文。
2. 登录成功后校验 `data.role === 1`。若 `data.must_change_password === true`，不要进入主界面；用 `data.change_password_url`（或再申请 `/api/web-sso-ticket`）打开浏览器改密页，改完后用新密码重新登录。
3. 进入主界面后，**30 分钟无鼠标/键盘操作**应自动退出登录并回到登录页。
4. 登录成功后调用 `GET /api/common_data/ftp/status` 一次；`data.available === false` 时提示「会影响数据分析」，**不要阻断登录或处置**。
5. **release 客户端**启动探测、登录前、进入主界面、以及待办定时刷新（10 分钟，含托盘）均调用 `GET /api/common_data/software/latest_version`。本地 `APP_VERSION` 落后于返回的 `version` 时，模态提示后**强制退出**（无「稍后」），请用户到软件中心安装新包。接口失败或 `version` 为空则放行。debug 模式不卡控。
6. Cookie 跨域时需服务端 CORS 与 `credentials` 配置匹配（本仓库 Web UI 同域部署为主）。
7. HTTPS 环境可将服务端 `HOLD_SESSION_SECURE=1`，Cookie 带 Secure。

### FTP 探活

`GET /api/common_data/ftp/status`

**Auth：** 已登录

探活数据分析用 testlog FTP（bysite / testlog 下载）。接口本身成功时 HTTP/code 均为 200；用 `data.available` 判断 FTP 是否通。

```json
{
  "code": 200,
  "msg": "FTP 可用",
  "data": {
    "available": true,
    "host": "172.18.200.250",
    "latency_ms": 42,
    "impact": null
  }
}
```

FTP 挂了时 `available` 为 `false`，`impact` 为给用户看的说明（数据分析可能受影响，Hold 流转不受影响）。

### 客户端版本

`GET /api/common_data/software/latest_version`

**Auth：** 无

读 `SOFTWARE_INFO` 第一行。发新包到软件中心时同步更新 `LATEST_VERSION`，并与客户端 `hold_client/version.py` 的 `APP_VERSION` 使用同一套点分数字。

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "version": "1.0.1",
    "comment": "请到软件中心安装最新客户端"
  }
}
```

`comment` 对应表中带引号列 `"comment"`。表空或查询失败时客户端不得踢人。

### root 维护版本

`GET /admin/software` 页面（仅 ROLE=0）。发新包后在此改版本号与发布说明；可从本机 git 历史生成说明草稿，保存前可再改。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/admin/software/api` | 当前 `LATEST_VERSION` / `comment`，以及建议下一版、客户端代码 `APP_VERSION` |
| PUT | `/admin/software/api` | Body `{ "version", "comment" }`，无行则插入 |
| GET | `/admin/software/api/changelog?client=1&backend=0&max_count=12` | 读旁边 `FT-HoldSys` / 本仓库 git log，返回 `comment_draft`（不写库） |

生产机若没有 git 仓库，changelog 的 `available=false`，改为手填 `comment`。

### 版本说明（Markdown）

全员可读页 `/release-notes`。root 按版本上传 `.md` / `.markdown`，一版本一份，发布新版本不覆盖旧文件。debug 写 `data/release_notes_test/{版本}.md`，release 写 `data/release_notes/{版本}.md`。

| 方法 | 路径 | Auth | 说明 |
| --- | --- | --- | --- |
| GET | `/release-notes` | 已登录 | 按版本列出全部说明 |
| GET | `/release-notes/api` | 已登录 | 返回 `items[]`：`version` / `html` / 上传人时间 |
| POST | `/release-notes/api` | root | `multipart`：`file` + 可选 `version`；同版本才覆盖该份 |

客户端「工具 → 版本说明」走 Web SSO，`POST /api/web-sso-ticket` 可带 `{ "next": "/release-notes" }`（`next` 仅允许该路径）。
