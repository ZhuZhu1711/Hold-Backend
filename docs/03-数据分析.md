# 03 数据分析

「数据分析」指工程师在 Holding 列表上对某条记录加载 **bysite 热图 / 缺陷 BIN**，用于研判后再做处置。

**不是**处置码 `5`（可靠性分析）。处置码 `5` 见 [04-处置规范.md](./04-处置规范.md)。

Web 端参考：`app/templates/eng/holds.html` 调用 `GET /admin/hold/api/analysis`。

**AQL_HOLD 例外：** `HOLD_CODE` 含 `AQL_HOLD` 时不要调用本接口。改为 `GET /admin/hold/api/annex_image?record_id=&index=` 展示 `ANNEX_FTP_PATH` 附件图；字段为空（`ANNEX_COUNT=0`）则不显示图片。详见 [07-手提Hold.md](./07-手提Hold.md)。

## 1. 主接口（推荐）

### `GET /admin/hold/api/analysis`

| 项 | 说明 |
| --- | --- |
| Auth | `@login_required`（工程师登录即可） |
| 实现 | `hold_report_ctrl.get_hold_analysis` |

### Query

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `wafer_id` | 是 | 完整 MES 片号，或展示串（`#03` / `#01#02`） |
| `lot_id` | 条件 | 展示串还原时**必填**；同 lot 分支需传 Holding 原始 `LOT_ID`（含合批后缀） |
| `record_type` | 建议 | Holding 行的 `RECORD_TYPE`（`0`/`2`；`1` 不调本接口） |
| `station` | 是 | **仅** `WLT2` / `FATE-FA` / `VBOX-FA`（非法或缺省 → 400） |

**调用方推导 `station`（勿再传 Holding 行原始 `STATION`）：**

| `RECORD_TYPE` | 规则 | `station` |
| --- | --- | --- |
| `0`（FT） | `LOT_ID` 含 `-` | `FATE-FA` |
| `0`（FT） | `LOT_ID` 不含 `-`（含空） | `VBOX-FA` |
| `2`（WLT） | — | `WLT2` |
| `1`（FVI） | **不调用**本接口 | 改调 FVI 缺陷明细 |

示例：

```
GET /admin/hold/api/analysis?wafer_id=%2301%2302&lot_id=C123-01&record_type=2&station=WLT2
GET /admin/hold/api/analysis?wafer_id=ABC01&lot_id=ABC01&record_type=0&station=VBOX-FA
GET /admin/hold/api/analysis?wafer_id=C123-01&lot_id=C123-01&record_type=0&station=FATE-FA
```

### 同 lot 查询规则

服务端按 `record_type` 与**原始** `lot_id`（`'-'` 后数字位数）枚举同 lot 片：

| 条件 | 行为 |
| --- | --- |
| `record_type=1`（FVI） | 仅当前片（无同 lot 概念；客户端一般不调本接口） |
| `record_type=2`（WLT） | 取 `lot_id` 在 `'-'` 前的前缀，`TEST_WAFER.WAFER_ID LIKE '[prefix]%'` |
| `record_type=0` 且后缀位数 == 2（或非合批后缀） | 同 WLT：前缀 LIKE |
| `record_type=0` 且后缀位数 > 2 | `SPLIT_MERGE_HISTORY` 查源片 → 各源片 `'-'` 前缀合并一次 LIKE；源片标 `is_merge_source` |

实现上用一条批量 SQL（`ROW_NUMBER` 按 `WAFER_ID` + 规范化工序取最新 `TEST_WAFER` + `LEFT JOIN TEST_BINCODE`）拉齐同 lot BIN，避免按片 N+1。同 lot 同时查 **WLT（`OPERATION_ID=WLT2`）和 FT FA（`FA` / `FATE-FA` / `VBOX-FA`）**；`FA` 与 `FATE-FA` 视为同一站。同一片两站都有数据时 `same_lot_rows` 拆成两行。**仅展示 `TEST_WAFER` 命中的片**（当前片除外，始终保留）；合批源片若无单片测试记录则不进 `same_lot_rows`。每次 `/api/analysis` 会把实际执行的 SQL 与参数写入 `logs/test_log.log`（`analysis SQL[...]`）。

### 服务端参数映射

由标准化 `station` 直接映射（与 `record_type` 解耦）。`station` **只影响 bysite** 与兼容字段 `raw_data`；同 lot BIN 始终拉 WLT + FA：

| `station` | bysite step 组 | 查询步 | 兼容 `operation_id` / `raw_data` |
| --- | --- | --- | --- |
| `WLT2` | `WLT` | `['WLTA','WLTB']` | 主片 `WLT` 行 |
| `FATE-FA` | `ATE` | `['FA']` | 主片 `FA` 行 |
| `VBOX-FA` | `ATE` | `['FA']` | 主片 `FA` 行 |

### 成功响应 `data`

```json
{
  "wafer_id": "C123-01",
  "wafer_id_display": "#01",
  "lot_id": "C123",
  "lot_id_raw": "C123-01",
  "resolved_wafer_ids": ["C123-01", "C123-02"],
  "record_type": 2,
  "station": "WLT2",
  "step": "WLT",
  "step_list": ["WLTA", "WLTB"],
  "operation_id": "WLT2",
  "bysite": "...或结构化 bysite 数据...",
  "bysite_msg": "获取成功",
  "raw_data": {},
  "raw_msg": "...",
  "is_merged": false,
  "source_lot_ids": [],
  "source_raw_data": {},
  "same_lot_rows": [
    {
      "wafer_id": "C123-01",
      "is_current": true,
      "is_merge_source": false,
      "lot_prefix": "C123",
      "die_num": 50000,
      "operation_id": "WLT2",
      "station": "WLT",
      "test_time": "2026-08-01 10:00:00",
      "raw_data": {"1": 10}
    },
    {
      "wafer_id": "C123-01",
      "is_current": true,
      "is_merge_source": false,
      "lot_prefix": "C123",
      "die_num": 50000,
      "operation_id": "FA",
      "station": "FA",
      "test_time": "2026-08-10 14:30:00",
      "raw_data": {"1": 8}
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `bysite` | 主片 FTP testlog bysite；失败时可为 `null`，见 `bysite_msg` |
| `raw_data` | 主片在请求 `station` 对应工序（WLT 或 FA）上的最新缺陷 BIN；无该站数据时回退该片其它站，失败多为 `{}` |
| `lot_id` | 规范化后的 lot 前缀（`'-'` 前） |
| `lot_id_raw` | 请求传入的原始 `LOT_ID` |
| `same_lot_rows` | 同 lot 列表，**每片每站一行**；含 `is_current` / `is_merge_source` / `lot_prefix` / `die_num`（`TEST_WAFER.GROSS_DIE`） / `operation_id` / `station`（`WLT` 或 `FA`） / `test_time`（`NVL(FT_TIME, RECORD_DTTM)`） / `raw_data`。排序：当前片 → 合批源 → `wafer_id` → `test_time` 升序 |
| `is_merged` / `source_lot_ids` / `source_raw_data` | 合批源片（兼容旧客户端）；合批时 `source_lot_ids` 为 merge 历史源片 |
| `resolved_wafer_ids` | 展示串展开后的真实片号列表 |

**注意：** bysite 依赖 FTP/testlog；FTP 异常时分析可能只有部分数据，**不影响**处置写库。客户端应对 `bysite == null` 做友好提示，勿阻塞处置入口。

登录后可用 `GET /api/common_data/ftp/status` 预先判断 FTP 是否通（见 [01-鉴权与通用约定.md](./01-鉴权与通用约定.md)）。

### 失败

| HTTP | 典型 msg |
| --- | --- |
| 400 | `请指定 wafer_id` / `展示串 Wafer 需同时指定 lot_id` / `station 仅支持 WLT2/FATE-FA/VBOX-FA` |

## 2. FVI 缺陷明细（辅助）

当 `RECORD_TYPE = 1`（FVI）时，**不要**调用 `/analysis`，改查 Lot 缺陷明细。

### `GET /eng/api/fvi_defect_details`（工程师） / `GET /admin/hold/api/fvi_defect_details`（root）

| 项 | 说明 |
| --- | --- |
| Auth | eng：`@engineer_required`；admin：`@root_required` |
| 权限（eng） | 该 `lot_id` 须出现在工程师所属型号的 FVI Hold Record 中 |

| Query | 必填 | 说明 |
| --- | --- | --- |
| `lot_id` | 是 | Holding 行的 `LOT_ID` |
| `line_type` | 否 | 默认 `FT` |

**比率口径：**

| 指标 | 公式 |
| --- | --- |
| 行 `ratio` | `qty / grade_num_total × 100%`（`grade_num_total` 为 0 → `-`） |
| `defect_ratio`（总缺陷占比） | `total_qty / grade_num_total × 100%` |

`grade_num` 取自同 `lot_id` 最新一条 `RECORD_TYPE=1` 的 `FT_HOLD_RECORD.GRADE_NUM`。

**成功 `data`：**

```json
{
  "lot_id": "C123",
  "line_type": "FT",
  "items": [
    {
      "defect_code": "A01",
      "defect_code_raw": "...",
      "defect_desc": "Scratch",
      "qty": 3,
      "grade": "HA",
      "ratio": "0.25%"
    }
  ],
  "summary": "A01 Scratch×3；...",
  "total_qty": 50,
  "count": 2,
  "grade_num": "F:1151,HA:49",
  "grade_num_display": "F:1151, HA:49",
  "grades": [{"grade": "F", "qty": "1151"}, {"grade": "HA", "qty": "49"}],
  "grade_num_total": 1200,
  "defect_ratio": "4.17%"
}
```

失败：`403`（Lot 不在所属 FVI）/ `400`（缺 lot_id）。

## 3. 与处置码 5 的区别

| | 数据分析 API | 可靠性分析处置 |
| --- | --- | --- |
| 用途 | 读测试/缺陷数据 | 写流转意见 |
| 接口 | `GET .../analysis` | `POST /eng/api/dispose`，`dispose=5` |
| 副作用 | 无写库 | 插入 `CIRCULATION_HISTORY`，`NEXT`→生产 OP |

客户端流程应是：**先分析（可选）→ 再选择处置行为（含可选的可靠性分析）**。

## 4. 附录：底层接口（一般不必直连）

聚合接口已封装下列能力；仅在自定义分析 UI 时参考：

| 路径 | 参数 | 说明 |
| --- | --- | --- |
| `GET /api/test_data/bysite` | `wafer_id`, `step`=`ATE`\|`WLT` | bysite |
| `GET /api/raw_data/defect_bincode` | `wafer_id`, `operation_id` | 缺陷 BIN |
| `GET /api/test_data/ftp_path` | `product_id`, `wafer_id`, `step` | FTP 路径列表 |
