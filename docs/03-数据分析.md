# 03 数据分析

「数据分析」指工程师在 Holding 列表上对某条记录加载 **bysite 热图 / 缺陷 BIN**，用于研判后再做处置。

**不是**处置码 `5`（可靠性分析）。处置码 `5` 见 [04-处置规范.md](./04-处置规范.md)。

Web 端参考：`app/templates/eng/holds.html` 调用 `GET /admin/hold/api/analysis`。

---

## 1. 主接口（推荐）

### `GET /admin/hold/api/analysis`

| 项 | 说明 |
| --- | --- |
| Auth | `@login_required`（工程师登录即可） |
| 实现 | `hold_report_ctrl.get_hold_analysis` |

### Query

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `wafer_id` | 是 | 完整 MES 片号，或展示串（`#03` / `#01#02`） |
| `lot_id` | 条件 | 当 `wafer_id` 以 `#` 开头时**必填**，用于还原真实片号 |
| `record_type` | 建议 | Holding 行的 `RECORD_TYPE`（`0`/`1`/`2`） |
| `station` | 建议 | Holding 行的 `STATION` |

从列表行取值示例：

```
GET /admin/hold/api/analysis?wafer_id=%2301%2302&lot_id=C123&record_type=2&station=WOQC
```

### 服务端参数映射

由 `RECORD_TYPE` / `STATION` 推断：

| 条件 | bysite step 组 | raw `operation_id` |
| --- | --- | --- |
| `RECORD_TYPE=2`（WLT） | `WLT` → 查询步 `['WLTA','WLTB']` | `station`（如 `WOQC`） |
| `STATION` 以 `FATE` 开头 | `ATE`；`FATE-FA` → `['FA']` | 使用该 `station` |
| 其它 FT/FVI | 默认步 `['FA']` | `FATE-FA` |

### 成功响应 `data`

```json
{
  "wafer_id": "C123-01",
  "wafer_id_display": "#01",
  "lot_id": "C123",
  "resolved_wafer_ids": ["C123-01", "C123-02"],
  "record_type": 2,
  "station": "WOQC",
  "step": "WLT",
  "step_list": ["WLTA", "WLTB"],
  "operation_id": "WOQC",
  "bysite": "...或结构化 bysite 数据...",
  "bysite_msg": "获取成功",
  "raw_data": {},
  "raw_msg": "...",
  "is_merged": false,
  "source_lot_ids": [],
  "source_raw_data": {}
}
```

| 字段 | 说明 |
| --- | --- |
| `bysite` | 主片 FTP testlog bysite；失败时可为 `null`，见 `bysite_msg` |
| `raw_data` | 主片最新缺陷 BIN（qty 等）；失败时多为 `{}` |
| `is_merged` / `source_raw_data` | 合批或多片展示串时，附源片 raw_data |
| `resolved_wafer_ids` | 展示串展开后的真实片号列表 |

**注意：** bysite 依赖 FTP/testlog；FTP 异常时分析可能只有部分数据，**不影响**处置写库。客户端应对 `bysite == null` 做友好提示，勿阻塞处置入口。

### 失败

| HTTP | 典型 msg |
| --- | --- |
| 400 | `请指定 wafer_id` / `展示串 Wafer 需同时指定 lot_id` |

## 2. FVI 缺陷明细（辅助）

当 `RECORD_TYPE = 1`（FVI）时，可额外查询 Lot 缺陷明细。

### `GET /eng/api/fvi_defect_details`

| 项 | 说明 |
| --- | --- |
| Auth | `@engineer_required` |
| 权限 | 该 `lot_id` 须出现在工程师所属型号的 FVI Hold Record 中 |

| Query | 必填 | 说明 |
| --- | --- | --- |
| `lot_id` | 是 | Holding 行的 `LOT_ID` |
| `line_type` | 否 | 默认 `FT` |

**成功 `data`：**

```json
{
  "lot_id": "C123",
  "line_type": "FT",
  "items": [
    {
      "defect_code": "A01",
      "defect_code_raw": "...",
      "defect_desc": "Scratch",
      "qty": 3
    }
  ],
  "summary": "A01 Scratch×3；..."
}
```

失败：`403`（Lot 不在所属 FVI）/ `400`（缺 lot_id）。

## 3. 与处置码 5 的区别

| | 数据分析 API | 可靠性分析处置 |
| --- | --- | --- |
| 用途 | 读测试/缺陷数据 | 写流转意见 |
| 接口 | `GET .../analysis` | `POST /eng/api/dispose`，`dispose=5` |
| 副作用 | 无写库 | 插入 `CIRCULATION_HISTORY`，`NEXT`→生产 OP |

客户端流程应是：**先分析（可选）→ 再选择处置行为（含可选的可靠性分析）**。

## 4. 附录：底层接口（一般不必直连）

聚合接口已封装下列能力；仅在自定义分析 UI 时参考：

| 路径 | 参数 | 说明 |
| --- | --- | --- |
| `GET /api/test_data/bysite` | `wafer_id`, `step`=`ATE`\|`WLT` | bysite |
| `GET /api/raw_data/defect_bincode` | `wafer_id`, `operation_id` | 缺陷 BIN |
| `GET /api/test_data/ftp_path` | `product_id`, `wafer_id`, `step` | FTP 路径列表 |

**推荐始终优先调用 `GET /admin/hold/api/analysis`**（自动处理展示串展开、step/op 映射、合批源片）。
